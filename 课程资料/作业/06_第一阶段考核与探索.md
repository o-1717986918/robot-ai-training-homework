# 第一阶段：B站采集考核与 Sokoban 探索

## 一、需要配置的环境和工具

沿用 Windows Python 3.13、pip、编辑器和 Git。在 **Windows CMD** 中安装采集与分析所需库：

```bat
python -m pip install requests beautifulsoup4 pandas matplotlib opencv-python
python -c "import requests, bs4, pandas, matplotlib, cv2; print('依赖可用')"
```

`heapq` 是 Python 标准库，Sokoban 探索无需单独安装。培训方需发放核验的 B 站视频清单及可用同源快照。

## 二、最终任务与提交内容

### 需要学习的内容

- 学习 URL、HTTP 请求与响应、状态码、HTML 和 JSON，使用 Requests 与 BeautifulSoup 解析公开页面；练习按 URL 下载并读取图片。
- 学习超时、有限重试、异常记录、断点或重复运行，以及按 BVID 和图片 SHA-256 去重；用 Pandas 清洗 CSV、分组统计，用 Matplotlib 绘图。
- 学习用函数、类和模块组织采集、下载与分析流程；记录来源、缺失值和运行配置。
- **自选 Sokoban：**学习地图与状态表示、合法推箱、BFS、优先队列、A* 可容许启发式、死锁检测和路径回放。

**学习资源：**[Requests 快速入门](https://requests.readthedocs.io/en/latest/user/quickstart/)、[Pandas 入门](https://pandas.pydata.org/docs/getting_started/index.html)；自选阅读 [CS50 AI 搜索](https://cs50.harvard.edu/ai/2024/notes/0/)与 [OI Wiki A*](https://oi-wiki.org/search/astar/)。

### 必做：B站视频元数据与封面采集

**提交位置：** `phase1/assessment/`。

#### 题目描述

读取培训方核验的公开视频清单，采集视频元数据和封面图片，完成清洗、去重、统计与可视化。通过配置与统一命令行入口运行，使用类与模块组织采集、下载、数据处理等职责。

#### 输入与数据来源

输入 `videos.csv` 至少包含 50 个公开视频 BVID 或页面 URL。正式数据使用 B站页面或接口返回，或培训方发放的、标明来源与抓取日期的同源响应快照；保留 `live` / `snapshot` 数量。本地练习网页用于练习，正式计数采用 B站来源数据。培训方发放核验清单及可使用的快照。

#### 输出与约束

1. 获取不少于 **50 条视频元数据**和 **30 张按内容哈希去重的不同封面**。记录至少 `bvid,page_url,title,tags,view,like,favorite,cover_url,download_path,width,height,sha256,collected_at,source_mode,status,error`；缺失字段保留为空并记录原因，计数为非负整数。
2. 按 BVID 去重视频，按 SHA-256 去重图片；保存原始响应或记录、清洗后的 CSV、错误表与汇总结果。处理超时、有限重试、无效链接、坏图与重跑，避免静默覆盖；一条失败不终止整批。
3. 从标签、播放量分布、点赞／播放量关系、封面尺寸、下载状态中选至少两项分析，输出至少两张统计图。说明零分母处理与多标签计数规则。

#### 交付与验收

提交源代码、依赖、输入清单小样例、字段说明、运行命令、清洗规则、两张统计图、错误与重跑记录和报告。批量图片及原始响应通过可访问的存储链接提供，记录来源及 SHA-256；不要将密钥、大型数据集提交到 Git。验收 50／30 数量、两张图、异常不中断、可追溯与可复现。

### 自选：基于 A* 的 Sokoban 求解器

**提交位置：** `phase1/exploration/`。本题为自选，不计入基础通过条件。

#### 题目描述与输入

输入标准推箱子文本地图，识别墙、地面、目标、箱子与玩家；基础验证使用不超过 8×8、至多 3 个箱子的小图。`assets/sokoban/` 提供起始地图。

#### 输出与约束

以**推箱次数最少**为优化目标，玩家空走不计入推数。输出可逐步重放的行走／推箱动作，保证玩家能抵达箱后、箱子目的格可用，最终所有目标被占满。报告 `solved`、`unsolvable`、`invalid` 或 `timeout`；只有穷尽搜索才可报告无解。

使用推箱级 A*：每次推箱代价为 1，启发式为剩余推数的下界；区分静态地图、箱子集合和玩家可达区域。保存父状态与行走路径，处理可证明的非目标墙角死锁。

#### 交付与验收

提交求解程序、小地图、运行方式、动作回放和说明。使用相同代价的推箱级 BFS 在至少三类小地图上对照最少推数，报告推数、行走数、扩展状态与耗时；覆盖已完成、无解／死锁、非法输入和超时。

### 提交内容与检查

- 必做考核：在培训方仓库的考核分支提交 `phase1/assessment/` 下的采集、清洗、统计与可视化代码，依赖和 README，以及小样例、两张统计图、日志摘要和报告；报告记录 50 条元数据、30 张去重封面及异常处理结果。
- 大批图片和原始响应使用培训方可访问的存储链接，并记录来源与 SHA-256。PR 中填写运行命令和结果摘要。
- 自选 Sokoban：将代码、地图、回放和 BFS 对比结果提交到独立探索分支的 `phase1/exploration/`，并在培训方仓库另建 PR。

## 三、提交至作业仓库

培训方仓库：[https://github.com/o-1717986918/robot-ai-training-homework](https://github.com/o-1717986918/robot-ai-training-homework)。培训方为每位学员开通该仓库的写入权限。本文的 `GITHUB_USERNAME` 是占位符：请在每条命令中替换为自己的 GitHub 用户名，例如 `student/robotlee/phase1-task01`。每位学员使用自己的分支；提交的 PR 保留在培训方仓库，**不合并到培训方 main**。其他有仓库访问权限的学员可能看到分支和 PR。

1. 打开Windows CMD，在仓库目录从自己上一任务已推送的分支创建本任务分支：

```bat
cd /d C:\robot-ai\course
git status
git fetch origin
git switch -c student/GITHUB_USERNAME/phase1-assessment origin/student/GITHUB_USERNAME/phase1-task05
```

如果当前有需要保留的未提交修改，先完成提交。若本任务分支已在本机创建，将最后一条命令替换为 `git switch student/GITHUB_USERNAME/phase1-assessment`。

2. 完成本项内容，在仓库根目录执行，确认 `git status` 后推送：

```bat
cd /d C:\robot-ai\course
git add -- phase1/assessment
git status
git commit -m "Complete phase1-assessment"
git push -u origin student/GITHUB_USERNAME/phase1-assessment
```

3. 打开**培训方仓库**的 **Pull requests → New pull request**：选择 `base: main` 和 `compare: student/GITHUB_USERNAME/phase1-assessment`，填写任务名称、运行方法与结果，点击 **Create pull request**。按任务要求运行项目，检查输出并在 PR 中记录实际结果。

4. 保留 PR 和已推送分支，下一任务从本分支继续。将大量数据、模型或视频放在培训方可访问的存储位置，在 README 提供链接与 SHA-256；少量结果放任务目录的 `samples/`。不要提交密钥、虚拟环境和完整数据集。

**自选探索单独提交：**先执行以下命令至 `git switch`，创建 `student/GITHUB_USERNAME/phase1-exploration` 分支；在该分支完成并保存探索内容后，再执行 `git add` 及后续命令：

```bat
cd /d C:\robot-ai\course
git fetch origin
git switch -c student/GITHUB_USERNAME/phase1-exploration origin/student/GITHUB_USERNAME/phase1-assessment
git add -- phase1/exploration
git status
git commit -m "Complete phase1-exploration"
git push -u origin student/GITHUB_USERNAME/phase1-exploration
```

在培训方仓库创建 `base: main`、`compare: student/GITHUB_USERNAME/phase1-exploration` 的 PR。探索分支不会改变后续必做任务所用的考核分支。
