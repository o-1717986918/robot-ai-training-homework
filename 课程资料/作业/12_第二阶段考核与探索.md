# 第二阶段：CS 视频光标控制与多模态探索

## 一、需要配置的环境和工具

Ubuntu、`robot-ai-vision`、第二阶段任务4已安装的 PyTorch、YOLO、OpenCV、NumPy，另需 pySerial 和 socat。Ubuntu 终端中运行：

```bash
conda activate robot-ai-vision
python -m pip install pyserial
sudo apt update
sudo apt install -y socat
python -c "import serial, cv2, ultralytics; print(serial.__version__)"
socat -V
```

练习虚拟串口：在一个 Ubuntu 终端运行 `socat -d -d pty,raw,echo=0 pty,raw,echo=0`，记下输出的两条 `/dev/pts/...` 路径并保持该终端运行；另开两个终端，使用 pySerial 打开相应路径收发数据。[pySerial 教程](https://pyserial.readthedocs.io/en/latest/shortintro.html)。

界面任选：Web 方案执行 `python -m pip install fastapi uvicorn`，按 [FastAPI 教程](https://fastapi.tiangolo.com/tutorial/) 创建和启动服务；桌面方案执行 `python -m pip install PyQt6`，按 [PyQt6 文档](https://www.riverbankcomputing.com/static/Docs/PyQt6/) 创建窗口。自选多模态任务在 [智谱开放平台](https://open.bigmodel.cn/) 注册并创建 API Key，按 [模型调用说明](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.1v-thinking-flash) 核对模型 ID、可用性、费用与速率限制；密钥放环境变量或本地安全配置。培训方提供 CS 测试视频、标注和阈值。

## 二、最终任务与提交内容

### 需要学习的内容

- 复习视频逐帧读取、YOLO 结果与坐标转换，学习相邻帧目标关联、目标出现和消失处理。
- 学习欧氏距离、目标访问顺序枚举、动态重规划、速度限制与时间差计算；记录连续光标轨迹。
- 学习串口基本收发、pySerial、socat 虚拟串口及自定消息协议，处理消息边界、ACK、超时、断连和异常；选择 FastAPI + 前端或 PyQt6 制作界面。
- **自选多模态探索：**学习图片 API 调用、提示词、结构化 JSON 协议、本地校验、缓存、重试、统计与人工复核。
- **拓展导学：**了解强化学习的状态、动作、奖励和策略，尝试描述本场景的观测与动作。

**学习资源：**[pySerial 入门](https://pyserial.readthedocs.io/en/latest/shortintro.html)、[FastAPI 教程](https://fastapi.tiangolo.com/tutorial/)或 [PyQt6 文档](https://www.riverbankcomputing.com/static/Docs/PyQt6/)；可选[强化学习课程](https://www.bilibili.com/video/BV1sd4y167NS/)。

第二阶段可以使用 Agent 辅助；提交前自行运行、检查并解释代码。

### 必做：CS 视频识别与模拟光标控制

**提交位置：** `phase2/assessment/`。

#### 输入与输出

读取培训方提供的 CS 视频、类别表和 第二阶段任务4 训练权重，播放视频并叠加人物检测框、人数、敌方目标、**模拟光标**与连续轨迹。界面提供开始、暂停、停止、重播，以及敌方阵营、置信度、光标速度和命中半径设置。培训方发放视频、评测片段、目标位置／出现消失标注、有效范围、速度上限、命中半径与响应时延阈值；基础片段同时出现的有效敌方目标不超过 7 个。

#### 路径与通信规则

目标点为人物检测框中心，坐标使用原视频像素。静态快照从当前光标出发，访问所有有效目标一次并在最后一个目标结束，距离为欧氏距离；目标数不超过 7 时枚举并选择总长度最小的顺序，同长按目标 ID 顺序决胜。例：起点 `(0,0)`，A=`(3,0)`、B=`(3,4)`，A→B 长度为 7。

程序按 `frame_id / FPS` 统一视频时间轴，维持目标 ID、当前位置、速度及状态。每次位移不超过 `speed_px_s × delta_t`；目标出现、消失、命中、类别变化或过期时记录事件并重规划。记录连续轨迹、目标与命令，导出 CSV 和视频。

使用 `pySerial` 和 `socat` 的一对虚拟串口，自行设计编码、消息边界、版本、序号、时间戳、坐标、速度、ACK、超时及暂停／停止／重启／过期／重复命令处理；半包、粘包与坏消息应可处理，断连后停止移动。界面使用 FastAPI＋HTML/CSS/JavaScript 或 PyQt6。

#### 交付与验收

提交源码、依赖、协议文档、配置、README、一条仓库根目录启动命令、启动／停止顺序、轨迹 CSV、视频及异常记录；大视频、模型以链接与 SHA-256 提供。检查零目标、多目标最短顺序、新增／消失目标、连续速度、串口异常、暂停与重播；报告检测质量、目标数、首次响应时延、命中／重复次数、快照最优长度、实际轨迹长度、处理 FPS 与端到端延迟。

### 自选：多模态模型图片分类

**提交位置：** `phase2/exploration/`。本题为自选，不计入基础通过条件。

#### 输入与目标

复用 第一阶段采集考核 中获准使用的真实封面或其他获准语义图片，使用 GLM-4.1V-Thinking-Flash（模型 ID `glm-4.1v-thinking-flash`）分析图片可见内容。调用前核对官方模型可用性、计费与账户速率限制；密钥以环境变量或本地安全配置提供。

#### 输出与约束

自行定义有限类别、不确定出口、提示词及结构化文本协议；记录提示词和协议版本。本地检查 JSON、顶层类型、必要字段、图片 ID、字段类型和类别枚举；错误回复可有限次重试并保留失败状态。以图片哈希、模型、提示词和协议版本组成缓存键。导出分类与统计 CSV，并提供可人工查看、修正和记录结果的 Web 或 GUI 界面。

#### 交付与验收

提交分类代码、依赖、协议、提示词、验证与缓存／重试实现、复核界面、失败样例和独立评估报告。至少 50 张图片先独立人工标注，再评估首轮协议有效率、最终成功率、分类准确率或宏平均 F1、人工复核比例、耗时及调用量；报告至少一次提示词变化。大批原图、响应与 API 密钥不提交 Git，提供获准访问的小样例和链接；在线服务受限时记录实际完成情况。

### 提交内容与检查

- 必做考核：在培训方仓库的考核分支提交 `phase2/assessment/` 下的识别、目标选择、路径规划、虚拟串口和界面代码，依赖、协议、配置、README、轨迹 CSV 摘要和异常记录；视频及模型通过培训方可访问的链接提供并记录 SHA-256。
- README 说明启动与停止顺序、运行命令和指标，PR 记录零目标、多目标、目标变化、速度限制和串口异常等实际检查结果。
- 自选多模态分类：在独立探索分支提交 `phase2/exploration/` 下的代码、协议、提示词、缓存与重试、复核界面和评估报告，并在培训方仓库另建 PR。

## 三、提交至作业仓库

培训方仓库：[https://github.com/o-1717986918/robot-ai-training-homework](https://github.com/o-1717986918/robot-ai-training-homework)。培训方为每位学员开通该仓库的写入权限。本文的 `GITHUB_USERNAME` 是占位符：请在每条命令中替换为自己的 GitHub 用户名，例如 `student/robotlee/phase1-task01`。每位学员使用自己的分支；提交的 PR 保留在培训方仓库，**不合并到培训方 main**。其他有仓库访问权限的学员可能看到分支和 PR。

1. 打开Ubuntu 终端，在仓库目录从自己上一任务已推送的分支创建本任务分支：

```bash
cd ~/robot-ai/course
git status
git fetch origin
git switch -c student/GITHUB_USERNAME/phase2-assessment origin/student/GITHUB_USERNAME/phase2-task05
```

如果当前有需要保留的未提交修改，先完成提交。若本任务分支已在本机创建，将最后一条命令替换为 `git switch student/GITHUB_USERNAME/phase2-assessment`。

2. 完成本项内容，在仓库根目录执行，确认 `git status` 后推送：

```bash
cd ~/robot-ai/course
git add -- phase2/assessment
git status
git commit -m "Complete phase2-assessment"
git push -u origin student/GITHUB_USERNAME/phase2-assessment
```

3. 打开**培训方仓库**的 **Pull requests → New pull request**：选择 `base: main` 和 `compare: student/GITHUB_USERNAME/phase2-assessment`，填写任务名称、运行方法与结果，点击 **Create pull request**。按任务要求运行项目，检查输出并在 PR 中记录实际结果。

4. 保留 PR 和已推送分支，下一任务从本分支继续。将大量数据、模型或视频放在培训方可访问的存储位置，在 README 提供链接与 SHA-256；少量结果放任务目录的 `samples/`。不要提交密钥、虚拟环境和完整数据集。

**自选探索单独提交：**先执行以下命令至 `git switch`，创建 `student/GITHUB_USERNAME/phase2-exploration` 分支；在该分支完成并保存探索内容后，再执行 `git add` 及后续命令：

```bash
cd ~/robot-ai/course
git fetch origin
git switch -c student/GITHUB_USERNAME/phase2-exploration origin/student/GITHUB_USERNAME/phase2-assessment
git add -- phase2/exploration
git status
git commit -m "Complete phase2-exploration"
git push -u origin student/GITHUB_USERNAME/phase2-exploration
```

在培训方仓库创建 `base: main`、`compare: student/GITHUB_USERNAME/phase2-exploration` 的 PR。探索分支不会改变后续必做任务所用的考核分支。
